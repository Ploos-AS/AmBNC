# M5 — ARexx API

Status: IMPLEMENTED, runtime qualification pending.

AmBNC exposes the public Exec/ARexx port `AMBNC` while the bouncer is running.

## Commands

- `STATUS` — returns upstream/downstream state plus channel/buffer counts.
- `CONNECT` — reconnects/resumes a manually disconnected upstream session.
- `DISCONNECT` — disconnects upstream and holds it down until `CONNECT`.
- `JOIN <channel>`
- `PART <channel> [message]`
- `MSG <target> <text>`
- `NOTICE <target> <text>`
- `RAW <irc line>`
- `BUFFER` — returns bounded backlog target/line counts.
- `RELOAD` — control-plane hook reserved for configuration reload. M5 still uses CLI configuration, so no file is re-read yet.
- `QUIT` — cleanly stops AmBNC.

Commands that send IRC data require a live upstream connection.

## Event hooks

Optional scripts live in `REXX:AmBNC/` and are named after events:

- `ON_CONNECT.rexx`
- `ON_DISCONNECT.rexx`
- `ON_PRIVMSG.rexx`
- `ON_NOTICE.rexx`
- `ON_JOIN.rexx`
- `ON_PART.rexx`
- `ON_QUIT.rexx`
- `ON_KICK.rexx`
- `ON_TOPIC.rexx`
- `ON_NICK.rexx`

Missing hook files are ignored. Hooks receive four quoted arguments:

`EVENT NICK TARGET TEXT`

Lifecycle hooks use the event name plus connection detail in `TEXT`.

Hooks are synchronous in M5. A hook timeout/watchdog is deliberately deferred until runtime qualification shows the appropriate classic-Amiga behaviour.

## Execution model

The `AMBNC` message-port signal is multiplexed with upstream, listener, downstream and Ctrl-C via the existing `WaitSelect()` loop. ARexx therefore remains responsive during normal connected operation. After `DISCONNECT`, AmBNC waits on the ARexx port for `CONNECT` or `QUIT` without reconnecting upstream automatically.

## Qualification scope

M5 is implemented but not runtime-qualified. Local qualification must verify RexxMast interaction, result strings/return codes, command sends, DISCONNECT/CONNECT state transitions, hooks, and clean shutdown on an AmigaOS 2.04+ setup.
