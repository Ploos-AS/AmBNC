# M2 — Downstream client

M2 adds the first usable bouncer attachment path on top of the M1 upstream session.

## Listener

- One IPv4 listener is opened through `bsdsocket.library`.
- Default downstream TCP port: `16667`.
- A different port can be supplied as the final CLI argument.
- Only one downstream client is accepted at a time; extra clients receive a short busy notice and are closed.

## Attach semantics

The upstream session is already registered by AmBNC. Therefore downstream registration commands `PASS`, `NICK`, and `USER` are consumed locally rather than sent upstream. On attach the client receives a minimal synthetic `001` welcome indicating that it is attached to the existing AmBNC upstream session.

## Relay

- Upstream IRC lines are forwarded to the attached downstream client.
- Server `PING` is handled by AmBNC itself and is not delegated to the downstream client.
- Downstream commands other than local registration and `QUIT` are relayed upstream.
- Downstream `QUIT` detaches only the client; the upstream connection remains alive.
- Upstream loss closes the downstream client cleanly before the M1 reconnect loop resumes.

The upstream socket, listener socket, downstream socket, and Ctrl-C signal are serviced by one `WaitSelect()` loop.

## Qualification boundary

M2 is source-implemented. Native Bebbo build and FS-UAE/AROS/runtime qualification remain separate qualification work.
