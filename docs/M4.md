# M4 — Backlog playback

M4 replays bounded M3 backlog data when a downstream IRC client attaches to a live upstream session.

## Behavior

- Backlog is collected only while no downstream client is attached.
- Up to 16 target rings are retained.
- The per-target runtime limit is configurable from 1 to 32 lines.
- The default is 32 lines per target.
- When a ring is full, the oldest line is overwritten and the dropped counter is incremented.
- Each stored line records Amiga `DateStamp` day/minute/tick metadata.
- On downstream attach, AmBNC sends a summary NOTICE for each non-empty target, then a timestamp metadata NOTICE followed by the original IRC line.
- Original buffered IRC lines are replayed unchanged.
- A target ring is cleared only after its complete replay succeeds.
- If replay fails because the downstream connection disappears, replay stops and the client is detached; rings not yet completed remain buffered.

## CLI

```
AmBNC HOST PORT NICK [USER] [PASS] [LISTEN_PORT] [BACKLOG_LINES]
```

`BACKLOG_LINES` must be from 1 through 32. The default is 32.

## Qualification boundary

M4 implementation is present in `main`. Native Bebbo build and live FS-UAE/AmigaOS qualification remain separate.
