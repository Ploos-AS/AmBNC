# M6 — Multiple sessions

Status: IMPLEMENTED, runtime qualification pending.

AmBNC M6 adds an optional multi-network mode while preserving the legacy single-session CLI.

## Invocation

```text
AmBNC -c S:AmBNC.cfg
```

Configuration uses bounded `[NETWORK name]` sections. Up to four networks are supported.

Recognized keys per network:

- `HOST` — required
- `PORT` — default 6667
- `NICK` — required
- `USER` — defaults to `NICK`
- `PASS` — optional
- `LISTEN_PORT` — default 16667 plus network index
- `BACKLOG_LINES` — 1..32, default 32

See `examples/AmBNC-Multi.cfg`.

## Runtime model

Each network has its own:

- upstream TCP connection
- downstream listener
- one downstream client
- IRC framing state
- current nick/channel state
- bounded backlog rings
- reconnect state

All network sockets are serviced from one bounded `WaitSelect()` loop. This avoids one Amiga task per network and keeps the 68000 target predictable.

A disconnected network reconnects independently while the other sessions continue to be serviced. `DISCONNECT` through ARexx pauses all configured upstream sessions; `CONNECT`/reconnect resumes them.

## ARexx compatibility

The public port remains `AMBNC`.

M6 aggregates `STATUS`/buffer counters across networks. Legacy commands that send IRC data (`JOIN`, `PART`, `MSG`, `NOTICE`, `RAW`) are routed through the first currently connected network. Explicit per-network ARexx command routing is intentionally left for later hardening rather than changing the M5 command syntax silently.

Event hooks remain enabled. Lifecycle hook detail includes the network name and upstream endpoint. IRC message hooks retain the M5 argument contract and do not yet add a network argument.

## Scope not claimed

M6 does not claim native TLS, CAP or SASL; those belong to M7. It also does not claim runtime qualification on AmigaOS/FS-UAE yet.
