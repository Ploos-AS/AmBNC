# M3 — Session/state

M3 adds bounded session state on top of the M2 downstream relay.

## Session state

AmBNC tracks its current nick and up to 16 joined channels from upstream IRC events. State is updated even while no downstream client is attached.

Self-state is only changed by events that apply to the current AmBNC nick. A NICK from another user does not change local nick state; JOIN/PART only change channel state for the AmBNC nick, and KICK only removes a channel when AmBNC is the victim.

## Detached buffering

While no downstream client is attached, upstream PRIVMSG and NOTICE lines are stored in bounded per-target ring buffers:

- maximum 16 targets;
- maximum 32 IRC lines per target;
- oldest entry is overwritten when a ring is full;
- overwrite count is retained per ring.

Channel messages are keyed by channel. Private messages addressed to the current AmBNC nick are keyed by sender nick.

When a downstream client is attached, new upstream messages are relayed directly and are not added to the detached backlog.

## Lifetime

The upstream IRC session remains active while the downstream client is absent. The M3 state belongs to the current upstream connection and is reset after an upstream reconnect, because server-side channel membership must be rebuilt for the new IRC session.

M4 owns backlog playback, timestamps/metadata where feasible, and configurable replay limits. M3 only captures and bounds the state needed for that milestone.

Runtime qualification remains separate.
